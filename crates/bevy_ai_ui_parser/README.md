# bevy_ai_ui_parser

A JSON / OpenDesign HTML driven UI parser plugin for Bevy.

`bevy_ai_ui_parser` lets a Bevy game load UI generated by Open Design or a
compatible BUI JSON file and run it as native Bevy UI. It is designed for
**AI-generated game UI**: AI writes a constrained subset of HTML/CSS, a
compiler translates it to BUI IR JSON, and the runtime loads IR to spawn
native Bevy UI.

## Why This Plugin?

Bevy's native UI is built by writing Rust code (`commands.spawn((Node { ... },
Button, ...))`). There is no markup format, no style separation, and no
visual editor. This makes AI-generated UI difficult.

This plugin provides the missing layers:

| What Bevy lacks | What this plugin provides |
|-----------------|--------------------------|
| Markup format | Constrained HTML subset (like Unity UXML) |
| Style separation | CSS subset with cascade and selectors (like Unity USS) |
| Visual editor | `bui_editor` standalone binary |
| Data binding | `data-binding` one-way binding |
| Event abstraction | `data-action` semantic event routing |
| Compile-time validation | `bevy_strict_lint.py` + `bevy_capability_contract.json` |

### Comparison with Unity UI Toolkit / AITOUIToolkit

This plugin follows the same architecture as Unity UI Toolkit (UXML/USS) and
the AITOUIToolkit project: HTML as source of truth, compile to IR, runtime
loads IR. But because Bevy's layout engine (Taffy) is more capable than
Unity's (Yoga), the CSS support surface is **wider**:

| CSS Feature | Unity UIToolkit | This Plugin |
|-------------|----------------|-------------|
| Flexbox | ✅ | ✅ |
| CSS Grid | ❌ forbidden | ✅ supported |
| gap / row-gap / column-gap | ❌ forbidden | ✅ supported |
| z-index | ❌ forbidden | ✅ supported |
| box-shadow | ❌ forbidden | ✅ helper-layer approximation |
| filter (blur/brightness/...) | ❌ forbidden | ✅ approximation |
| clip-path / mask-image | ❌ forbidden | ✅ approximation |
| inline SVG | ❌ (external only) | ✅ resvg rasterization |
| box-sizing | ❌ (fixed border-box) | ✅ both border-box and content-box |
| transition / animation | ✅ transition only | ❌ (ECS-driven motion) |

### Design Principles

1. **HTML is source code, not a runtime format.** The runtime never parses
   HTML. HTML is compiled to IR JSON at build time.
2. **Constrained subset, not full HTML/CSS.** A capability contract
   (`bevy_capability_contract.json`) defines exactly what CSS is supported.
   Unsupported properties are degraded (approximated), not silently dropped.
3. **No JavaScript.** Behavior is expressed via `data-action-*` attributes
   and a static declarative DSL (`data-bui-actions`). The runtime does not
   execute arbitrary JS.
4. **Browser preview is free.** AI can write HTML, preview it in a browser,
   then compile to IR. The browser is the first-stage verification tool.
5. **AI-first workflow.** The OpenDesign integration provides a multi-agent
   pipeline (UX planner → artist → TA → programmer) with intent freeze,
   self-lint, and compile gates.

## Architecture

```
HTML (source) → compile to IR JSON → runtime loads IR → Bevy UI tree
```

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  AI writes   │     │  compile + lint  │     │  Bevy runtime    │
│  HTML + CSS  │ ──> │  HTML → IR JSON  │ ──> │  loads IR JSON   │
│  + data-*    │     │  bevy_strict_lint│     │  AiUiPlugin      │
└─────────────┘     └──────────────────┘     └─────────────────┘
       │                                            │
       ▼                                            ▼
 ┌─────────────┐                            ┌─────────────────┐
 │  Browser     │                            │  Bevy UI tree    │
 │  preview     │                            │  (ECS entities)  │
 └─────────────┘                            └─────────────────┘
```

The runtime never compiles HTML. `AiUiPlugin::from_path("*.ir.json")` is the
primary API; `from_html_path` exists for dev prototyping only.

## Quick Start

### Load pre-compiled IR JSON (recommended)

```rust
use bevy::prelude::*;
use bevy_ai_ui_parser::AiUiPlugin;

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_plugins(AiUiPlugin::from_path("ui/main_menu.ir.json"))
        .run();
}
```

### Load HTML at runtime (dev prototyping only)

```rust
app.add_plugins(AiUiPlugin::from_html_path("ui/main_menu/index.html"));
```

### Load from in-memory JSON string

```rust
app.add_plugins(AiUiPlugin::from_json(json_string));
```

### Load from in-memory HTML string

```rust
app.add_plugins(AiUiPlugin::from_html(html_string));
```

## CLI Tools

### Compile HTML to IR JSON

```bash
cargo run -p bevy_ai_ui_parser --bin compile_opendesign_html -- input.html output.ir.json [manifest.json]
```

Or programmatically:

```rust
use bevy_ai_ui_parser::opendesign_html_file_to_bui_json;

let json = opendesign_html_file_to_bui_json("ui/main_menu/index.html")?;
std::fs::write("ui/main_menu.ir.json", json)?;
```

### Validate BUI JSON

```bash
cargo run -p bevy_ai_ui_parser --bin validate_bui -- file.ir.json
```

Or programmatically:

```rust
use bevy_ai_ui_parser::{validate_bui_json_file, validate_bui_json_str};

validate_bui_json_file("ui/main_menu.ir.json")?;
validate_bui_json_str(&json_string)?;
```

## Interaction API

### Register game-side action handlers

HTML nodes declare actions via `data-action="my.action"`. Register ECS-side
handlers:

```rust
use bevy::prelude::*;
use bevy_ai_ui_parser::{AiUiPlugin, BuiActionAppExt};

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_plugins(AiUiPlugin::from_path("ui/main_menu.ir.json"))
        .add_bui_action_handler("game.start_matchmaking", |world, event| {
            info!("Button pressed: {} from node {}", event.action, event.id);
        })
        .run();
}
```

### Read BUI actions directly

```rust
use bevy::prelude::*;
use bevy_ai_ui_parser::BuiActionTriggered;

fn handle_actions(mut actions: MessageReader<BuiActionTriggered>) {
    for action in actions.read() {
        match action.action.as_str() {
            "game.start_matchmaking" => { /* ... */ }
            "garage.open" => { /* ... */ }
            _ => {}
        }
    }
}
```

### Update bound UI state from ECS

HTML nodes bind to state keys via `data-binding="some.key"`. Push updates:

```rust
use bevy::prelude::*;
use bevy_ai_ui_parser::{BuiBindingValue, BuiStateSet};

fn update_status(mut writer: MessageWriter<BuiStateSet>) {
    writer.write(BuiStateSet {
        key: "race.status".to_string(),
        value: BuiBindingValue::Text("MATCHMAKING...".to_string()),
    });
}
```

Supported `BuiBindingValue` variants:
- `Text(String)` — applied to `text.content`
- `Number(f32)` — applied to size-like targets (progress, slider)
- `Bool(bool)` — applied to `visibility`, toggle checked
- `Color(String)` — applied to visual or text color
- `StringList(Vec<String>)` — applied to semantic list nodes
- `ObjectList(Vec<HashMap<String, String>>)` — list nodes with keyed placeholders

## Supported Control Contracts

### Button

```html
<button id="play_button" data-action="game.start_matchmaking">PLAY</button>
```

Runtime: pointer press, focused `Enter`/`Space`, gamepad South all emit `Press`.
`disabled="true"` blocks dispatch.

### Toggle / Checkbox

```html
<input id="audio_toggle" type="checkbox" data-binding="settings.audio_enabled"
       data-action-change="settings.audio.changed" />
```

### Text Input

```html
<input id="account_input" type="text" value="Racer"
       data-binding="login.account"
       data-action-submit="login.submit"
       data-action-focus="login.focus"
       data-action-blur="login.blur" />
```

### Slider

```html
<input id="volume_slider" type="range" min="0" max="100" value="65" step="5"
       data-binding="settings.volume"
       data-action-change="settings.volume.changed" />
```

### ScrollView

```html
<section id="inventory_scroll" data-scroll-view="true"
         data-scroll-binding="inventory.list"
         data-action-scroll="inventory.scrolled"
         style="overflow-y: auto">
  ...
</section>
```

### DropDown

```html
<select id="difficulty_select" data-binding="settings.difficulty">
  <option value="easy">Easy</option>
  <option value="hard" selected="true" data-action-select="difficulty.changed">Hard</option>
</select>
```

## Static Action Contract (Declarative DSL)

```html
<script type="application/json" data-bui-actions>
{
  "actions": {
    "start-race": [
      { "op": "set-text", "binding": "race.status", "node": "race_status_text", "value": "MATCHMAKING..." },
      { "op": "delay", "ms": 900 },
      { "op": "set-text", "binding": "race.status", "node": "race_status_text", "value": "READY" }
    ]
  }
}
</script>
```

Supported operations: `set-text`, `set-binding`/`set-state`, `set-image`,
`set-selected-image`, `set-selected`, `set-visible`, `set-visual-state`,
`clear-visual-state`, `run-action`, `delay`/`wait`.

Bevy runtime does not execute arbitrary browser JavaScript.

## Focus Navigation

- Controls with a stable `id` enter the parser-generated focus order.
- Focus order follows the BUI document tree.
- `Tab` / `Shift+Tab` moves between controls.
- DPad up/down and arrow keys navigate.
- Pointer press moves focus to the pressed control.
- Focused pressable controls use `Enter`, `Space`, and gamepad South.

## BUI IR Data Model

The `BuiDocument` struct is the top-level IR. Key types are all publicly
exported:

| Type | Description |
|------|-------------|
| `BuiDocument` | Top-level IR: `version`, `scene_name`, `state_model`, `resources`, `root` |
| `BuiNode` | Recursive tree node: `id`, `kind`, `layout`, `style`, `content`, `semantics`, `children` |
| `BuiStyles` | ~60 CSS-like `Option<String>` fields (display, position, flex, grid, etc.) |
| `BuiVisuals` | Visual properties: background_color, border_color/width/radius, box_shadow |
| `BuiTextConfig` | Text content, font_size, font_color, font_path, line_height, etc. |
| `BuiImageConfig` | texture_path, image_mode, background_size/position/repeat, atlas, slicer |
| `BuiSemantics` | tab_group, progress, slider, scroll_view, dropdown, stage_fit |
| `BuiStateVisual` | Per-state style overrides (hovered, pressed, focused, selected) |
| `BuiInteractionModel` | Declarative action scripts (op-based DSL) |

### Runtime Resources

| Resource | Description |
|----------|-------------|
| `BuiDocumentResource(BuiDocument)` | The live editable document (persisted after spawn) |
| `BuiSourcePaths` | Source file paths for write-back |
| `BuiRootEntity(Entity)` | Root entity of the spawned BUI tree |

### Runtime Components

| Component | Description |
|-----------|-------------|
| `BuiId(String)` | Stable BUI node id on spawned entity |
| `BuiLogicTags(Vec<String>)` | Logic tags from node |

### Runtime Messages

| Message | Description |
|---------|-------------|
| `BuiActionTriggered` | Emitted when interaction fires an action |
| `BuiStateSet` | Push a binding value update |
| `BuiBindingUpdate` | Push a binding source update |

## Capability Contract

The plugin defines a machine-readable CSS/HTML support contract that serves
as the single source of truth for AI generation, linting, and compilation:

| File | Purpose |
|------|---------|
| `opendesign-integration/design-systems/bevy-ui/bevy_capability_contract.json` | CSS property support levels (P0 native / P1 helper-layer / P2 approximation / forbidden) |
| `opendesign-integration/design-systems/bevy-ui/bevy_html_tag_map.json` | HTML tag → BuiNodeType mapping |
| `opendesign-integration/design-systems/bevy-ui/bevy_ui_assets_schema.json` | Asset manifest JSON schema |
| `opendesign-integration/skills/bevy-ui-programmer/scripts/bevy_strict_lint.py` | Python linter that validates AI-generated HTML against the contract |

### CSS Fallback Tiers

| Tier | Behavior | Examples |
|------|----------|---------|
| **P0 Native** | Directly mapped to Bevy UI | flex, grid, position, margin, padding, width, height, background-color, border, font-size, color, opacity |
| **P1 Helper-layer** | Approximated via child entity layers | box-shadow, text-shadow, drop-shadow, multi-layer gradient |
| **P2 Approximation** | Best-effort visual approximation | clip-path (contour), mask-image (fade), filter blur (low-opacity shadow), mix-blend-mode (multiply darken) |
| **Forbidden** | Not supported, dropped silently | animation/@keyframes, !important, external CSS files, attribute selectors, sibling selectors, :not/:is/:has/:nth-* |

### HTML Tag Mapping

| HTML tag | BuiNode kind | Notes |
|----------|-------------|-------|
| `<div>`, `<section>`, `<header>`, `<footer>`, `<nav>`, `<main>` | `node` | Generic container |
| `<span>`, `<p>`, `<label>`, `<h1>`–`<h6>`, `<strong>`, `<em>` | `text` | Text content |
| `<button>`, `role="button"`, `.btn`/`*-btn`/`*-button` | `button` | Interactive button |
| `<img src>` | `image` | Image node |
| `<input type="text">` | `text_input` | Editable text field |
| `<input type="checkbox">` | `toggle` | Toggle/checkbox |
| `<input type="range">` | `slider` | Range slider |
| `<select>` / `<option>` | `node` + dropdown semantics | Dropdown selection |
| `<br>` | (merged into text) | Line break within text |
| `<style>` | (extracted) | CSS rules, not a node |
| `<svg>` | `image` (rasterized) | Inline SVG → PNG via resvg |

## AI Workflow (OpenDesign Integration)

The `opendesign-integration/` directory contains a complete multi-agent
pipeline for AI-generated Bevy UI:

```
PM Brief → UX Planner (wireframe) → Artist (assets) → TA (motion) → Programmer (HTML/CSS) → Compile → Validate → Bevy runtime
```

### Pipeline stages

1. **Intent Freeze** — AI outputs `intent.json` (brief, resolution, pages, style axes). User approves before any HTML is written.
2. **Author HTML** — AI writes one `.html` per page with CSS in `<style>` tags.
3. **Self-lint** — `bevy_strict_lint.py` validates HTML against the capability contract. Max 3 auto-fix iterations.
4. **Compile** — `compile_opendesign_html` translates HTML → IR JSON + SVG→PNG.
5. **Verify** — Human reviews browser preview + Bevy runtime rendering.

### Sub-skills

| Role | Responsibility |
|------|---------------|
| `bevy-ux-planner` | Wireframe layout, scope, page list |
| `bevy-ui-artist` | Art asset generation (MiniMax/ComfyUI), SVG icons |
| `bevy-ui-ta` | Motion boundaries, state checklist |
| `bevy-ui-programmer` | HTML/CSS assembly, structure contract, self-check |
| `bevy-ui-generator` | SOP and pre-export checklist |

### Sync to Open Design

```bash
./opendesign-integration/sync_to_od.sh [--dry-run] /path/to/open-design
```

## Asset Loading

Image URLs in CSS and `<img src>` are resolved through Bevy's `AssetServer`.
Set the asset root to the folder containing the original HTML/IR file:

```rust
app.add_plugins(DefaultPlugins.set(AssetPlugin {
    file_path: "ui/main_menu".to_string(),
    ..default()
}));
```

## Supported HTML/CSS Subset

See `opendesign-integration/design-systems/bevy-ui/DESIGN.md` for the full
support matrix. Key highlights:

- **Layout**: flex, grid, position (absolute/relative/fixed), box-sizing, overflow, gap, z-index
- **Text**: font-family/size/weight, line-height, letter-spacing, text-align, white-space, CJK linebreak
- **Image**: `<img>`, background-image, background-size/position/repeat
- **Effects**: box-shadow, text-shadow, filter (blur/brightness/contrast/saturate), gradient fallback, clip-path/mask-image approximation
- **SVG**: inline SVG via resvg rasterization (0.44 + tiny-skia 0.11)
- **State**: `:hover`, `:active`, `:focus`, `:focus-visible`, `:disabled`, `:checked`, `.active`/`.selected`
